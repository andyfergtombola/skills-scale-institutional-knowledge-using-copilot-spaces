# OctoAcme Onboarding Checklist

## Purpose
Provide a clear, structured onboarding path for new team members joining OctoAcme projects. This checklist ensures consistent onboarding experiences and reduces time-to-productivity.

## Target Audience
- New developers, product managers, project managers, and other team members
- Managed by Onboarding Specialist in coordination with Project Managers and HR

---

## Week 1: Foundation & Access

### Administrative Setup
- [ ] Complete HR onboarding and paperwork
- [ ] Receive equipment and verify setup (laptop, monitors, accessories)
- [ ] Set up company email and communication accounts
- [ ] Join relevant Slack/Teams channels (team channel, announcements, social)
- [ ] Add to project distribution lists and calendar invitations

### Access & Accounts
- [ ] GitHub organization access granted
- [ ] Access to project repositories verified
- [ ] Project management tools access (Jira, Linear, GitHub Projects, etc.)
- [ ] Documentation platforms access (Confluence, Wiki, etc.)
- [ ] CI/CD and deployment tools access (as appropriate for role)
- [ ] Calendar invitations for recurring meetings (standups, syncs, all-hands)

### Initial Orientation
- [ ] Meet with Onboarding Specialist for overview session
- [ ] Introduction to team members and key stakeholders
- [ ] Review team org chart and reporting structure
- [ ] Understand team communication norms and preferences
- [ ] Tour of office/remote work setup and facilities (if applicable)

### Documentation Review
- [ ] Read [Project Management Overview](octoacme-project-management-overview.md)
- [ ] Review [Roles & Personas](octoacme-roles-and-personas.md) - identify your role
- [ ] Understand [Risk Management & Communication](octoacme-risks-and-communication.md) practices
- [ ] Familiarize with [Execution & Tracking](octoacme-execution-and-tracking.md) workflows
- [ ] Review current project charter or one-pager
- [ ] Explore project repository structure and key directories

---

## Week 2: Deep Dive & Integration

### Process Understanding
- [ ] Shadow a team standup and ask questions
- [ ] Review recent sprint/iteration plans and backlogs
- [ ] Understand Definition of Done and acceptance criteria standards
- [ ] Learn about quality gates and testing practices
- [ ] Review recent retrospective notes and improvement actions
- [ ] Study escalation paths and when to use them

### Tools & Workflows
- [ ] Set up local development environment (for technical roles)
- [ ] Complete first code review or documentation review
- [ ] Practice using project board/task management system
- [ ] Learn CI/CD pipeline and deployment process
- [ ] Understand version control and branching strategy
- [ ] Configure IDE/editor with team standards and plugins

### Role-Specific Activities
#### For Developers:
- [ ] Review codebase architecture and key components
- [ ] Set up and run test suite locally
- [ ] Complete a "good first issue" or small bug fix
- [ ] Participate in code review process
- [ ] Pair program with experienced team member

#### For Product Managers:
- [ ] Review product roadmap and prioritization framework
- [ ] Meet with key stakeholders and customers (shadowing calls)
- [ ] Understand metrics and success criteria
- [ ] Review user research and feedback channels
- [ ] Draft acceptance criteria for a sample feature

#### For Project Managers:
- [ ] Review current project plans and timelines
- [ ] Understand risk register and tracking practices
- [ ] Shadow stakeholder sync and weekly status update
- [ ] Practice using project templates and checklists
- [ ] Observe meeting facilitation techniques

#### For QA Leads:
- [ ] Review test strategy and quality standards
- [ ] Understand test automation framework
- [ ] Execute manual test scenarios
- [ ] Review defect tracking and triage process
- [ ] Participate in quality gate review

---

## Week 3-4: Active Contribution

### Ownership & Collaboration
- [ ] Take ownership of first substantial task or feature
- [ ] Participate actively in planning or estimation sessions
- [ ] Ask questions and seek clarification when needed
- [ ] Provide input in retrospectives and team discussions
- [ ] Begin building relationships with cross-functional partners

### Feedback & Growth
- [ ] Schedule 1:1 with manager to discuss progress
- [ ] Identify areas for additional training or support
- [ ] Share onboarding feedback with Onboarding Specialist
- [ ] Document any gaps or improvements for onboarding process
- [ ] Set initial performance goals and development objectives

### Knowledge Building
- [ ] Attend relevant team meetings (planning, demos, retrospectives)
- [ ] Review and understand current sprint goals
- [ ] Learn about upcoming projects and roadmap
- [ ] Explore related documentation and resources
- [ ] Join optional learning sessions or tech talks

---

## 30-Day Checkpoint

### Self-Assessment
- [ ] Can navigate project documentation independently
- [ ] Understand role responsibilities and expectations
- [ ] Know when and how to escalate issues
- [ ] Comfortable using core tools and workflows
- [ ] Have made meaningful contributions to the project
- [ ] Established working relationships with team members

### Manager Review
- [ ] Meet with manager for 30-day review
- [ ] Discuss progress against initial goals
- [ ] Identify strengths and development areas
- [ ] Adjust onboarding plan if needed
- [ ] Set objectives for next 60 days

### Onboarding Specialist Follow-up
- [ ] Complete onboarding feedback survey
- [ ] Share suggestions for improving onboarding experience
- [ ] Confirm all access and setup items are complete
- [ ] Transition from active onboarding to regular team member status

---

## 60-Day Checkpoint

### Integration Milestones
- [ ] Independently complete tasks with minimal guidance
- [ ] Contribute to team ceremonies (standups, planning, retros)
- [ ] Demonstrate understanding of quality and delivery standards
- [ ] Build productive working relationships across the team
- [ ] Provide helpful feedback in code/design reviews

### Manager Check-in
- [ ] Review progress and performance
- [ ] Discuss career development and growth opportunities
- [ ] Adjust goals and expectations as needed
- [ ] Celebrate successes and learning moments

---

## 90-Day Checkpoint

### Full Integration
- [ ] Operating as fully productive team member
- [ ] Taking on complex tasks and features
- [ ] Mentoring or supporting newer team members
- [ ] Contributing to process improvements
- [ ] Aligned with team culture and values

### Final Review
- [ ] Complete formal 90-day performance review
- [ ] Reflect on onboarding journey and growth
- [ ] Set long-term career development goals
- [ ] Transition to regular performance management cycle

## Continuous Improvement

This onboarding checklist is a living document. If you identify gaps, unclear instructions, or opportunities for improvement, please:
1. Share feedback with your Onboarding Specialist
2. Submit suggestions via the process improvement issue template
3. Help update this document for future team members

**Remember**: Onboarding is a journey, not a destination. It's normal to feel overwhelmed initially. Ask questions, seek help, and give yourself time to learn and grow!
