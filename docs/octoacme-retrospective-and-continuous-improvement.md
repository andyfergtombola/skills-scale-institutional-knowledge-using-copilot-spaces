# OctoAcme — Retrospective & Continuous Improvement

## Purpose
Capture learnings and convert them into actionable improvements.

## When
After each sprint, release, or important milestone. Also after incidents.

## Structure
- What went well
- What could be improved
- Action items (owner, due date)
- Follow-up on previous action items

## Retrospective Checklist

Use this checklist when facilitating or participating in retrospectives:

### Before the Retrospective
- [ ] Schedule retrospective within 1-2 days of sprint/release completion
- [ ] Send calendar invitation with agenda and preparation instructions
- [ ] Set up anonymous idea board or collaboration tool (Miro, Jamboard, etc.)
- [ ] Review previous retrospective action items and progress
- [ ] Gather relevant data (metrics, incidents, completion rates)
- [ ] Identify specific topics or themes to discuss if needed

### During the Retrospective (Timebox: 45-75 minutes)
- [ ] Start with icebreaker or check-in (5 minutes)
- [ ] Review ground rules (psychological safety, focus on process not people)
- [ ] Review previous action items and celebrate progress (10 minutes)
- [ ] Collect "What went well" items (10-15 minutes)
- [ ] Collect "What could be improved" items (10-15 minutes)
- [ ] Group and prioritize themes (10 minutes)
- [ ] Identify 2-3 top action items to focus on (10-15 minutes)
- [ ] Assign owners and due dates to action items
- [ ] Close with appreciations and summary (5 minutes)

### After the Retrospective
- [ ] Document retrospective notes in project repository
- [ ] Create action items in project backlog with clear owners and timelines
- [ ] Share summary with stakeholders (within 24 hours)
- [ ] Add action items to weekly PM sync agenda
- [ ] Schedule follow-up review for action item progress
- [ ] Archive retrospective board/notes for future reference

## Example Action Item Template
- **Title:** [Clear, concise description of the improvement]
- **Description:** [Detailed explanation of what needs to change and why]
- **Owner:** [Person responsible for driving the action]
- **Due date:** [Specific target completion date]
- **Success criteria:** [How we'll know this is successfully implemented]
- **Dependencies:** [Any blockers or prerequisites]
- **Status:** [Not Started / In Progress / Completed / Blocked]

### Sample Action Items
1. **Title:** Improve test coverage for API endpoints
   - **Description:** Several API endpoints lack integration tests, leading to undetected bugs. Add tests for top 5 most-used endpoints.
   - **Owner:** Sarah (Developer)
   - **Due date:** End of next sprint
   - **Success criteria:** Test coverage >80% for targeted endpoints, CI passing consistently

2. **Title:** Reduce meeting duration for daily standups
   - **Description:** Standups often run over 15 minutes. Implement timer and parking lot for detailed discussions.
   - **Owner:** Alex (Project Manager)
   - **Due date:** Immediately (next standup)
   - **Success criteria:** Average standup duration <15 minutes for 2 weeks

## Continuous Improvement Culture
- Measure impact of action items
- Celebrate improvements and make small, iterative changes
